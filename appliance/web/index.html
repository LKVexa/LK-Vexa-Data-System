ENVIRONMENT & BOUNDARIES
Choose your connection.
Both modes run the same virtual command engine. Browser Worker needs a secure browser context. Neither executes a host shell.

 
Transport
Defaults to this page’s server. Other endpoints must be permitted by both servers’ origin/CSP configuration. Tokens never belong in the URL.
Run "BOOT.cmd --network" --show-token to print the 64-character client token. It grants shared terminal access and is kept in page memory only.
Switching modes closes the current terminal sessions. The two modes have separate virtual volumes.
Browser Worker: origin-scoped IndexedDB, one writer per browser page. WebSocket: a shared server-side snapshot, up to eight authenticated sessions. Configurable network binding, exact allowed origins and token authentication. Use WSS for protected traffic; HTTP/WS requires explicit test-network opt-in.

 
Storage & evidence
Browser storage is not a physical SSD and may be cleared or evicted. Server storage contains virtual files only. Export important work.
Operating boundaries
Hardware, BMC, kernel, storage-array, and cluster commands are visible as references. They need a separately authorized execution environment.
DF nodes are metadata records, not running VMs. Image hashes detect content changes; they are not signatures or hardware attestation.

 
Runtime ledger
Execution needs the native owner window. The broker is not a headless command engine or a hardware data center. Photon snapshots do not back up terminal files.
